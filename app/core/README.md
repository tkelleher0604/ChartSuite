# The core

Classic scripts, each exposing one global and touching no page: `Tree` (tree.js), `Notes` (notes.js), `Log` (log.js) and `Formulas` (formulas.js), loaded in that order; then `Layout` and `Scene`, `SharePoint` and `Store`, which say what they do in their own headers. Terms are data-model.md's and dendra.md's. Tests: [../tests/core-test.html](../tests/core-test.html) and [../tests/engine-test.html](../tests/engine-test.html).

`TextTemplate` (text.js) loads before `Scene`. It parses the text shared by designs, scoped annotations and table cells, independently of records and the DOM. `parts(text)` separates literal text from explicit `{Field}` tokens; `render(text, read)` substitutes each field once through the supplied reader, preserving the surrounding whitespace. `fields` and `single` identify bindings; `literal` encodes typed text, escaping backslashes, braces and a leading equals sign. Existing unescaped field tokens and formula strings retain their syntax. Field values are never parsed again. See [text-test.html](../tests/text-test.html) and [the editor review guide](../../docs/editor-text-review.md).

Rich text `runs` use character offsets in the editor's text, before `TextTemplate.literal` adds storage escapes. A drawing converted into a design keeps those offsets. Scene decodes literal escapes before relocating runs for substituted fields; when the resulting text is unchanged, it retains the exact ranges, including repeated words and surrounding spaces.



`characters(source)` returns that offset text, leaving field token spellings intact. `editRuns(before, after, runs)` maps one contiguous edit by its unchanged prefix and suffix: retained characters keep their formatting, new or replacement characters are unformatted, and deleted characters lose their ranges. The shared [WordsEditor](../ui/words.js) applies this after each input and emits source plus runs together. Its adapter supplies offered fields, field creation, read-only state and persistence; the control has no record/schema lookup or transaction access.

`renderRuns(source, read, runs)` substitutes tokens and projects their formatting in the same pass. Literal ranges map by position, so repeated words remain distinct. A range covering a whole token formats its entire replacement value; a partial-token range does not format that value. Empty values contribute no range. Scene uses these transient projected ranges for drawings, designs, annotations and table cells; source ranges remain unchanged in the workbook. Formula results retain the existing fallback. Design-part descriptors also expose transient `sourceIds` for visible resolved fields, so mixed text can report which fields it shows.

`Formatting` (formatting.js) loads after `Tree` and `Notes`. It plans formatting changes without `App`, `Canvas`, UI controls or a DOM. `plan(context, label, value)` returns transient note/update commands; `apply(tx, commands)` writes them into one existing transaction. The context supplies records, the notes index, view, explicit selection, resolved scope and the marks that scope reaches. Shape rows and the current footer value come from the transaction, so setting several properties together does not discard an earlier setting.

The command layer owns the persisted behavior: a selection changes its own records in the current view; a shared scope writes patterns while preserving instance overrides; whole-object text formatting clears only that property's instance field overrides; whole-table text formatting clears only that property on cells; and failing-check styles remain chart-wide. Toolbar controls resolve intent before planning. Design-part and rich-text editing remain specialized adapters. The format painter uses the same field-override commands, rather than a second copy of their policy. [formatting-test.html](../tests/formatting-test.html) checks these contracts with real logs, including Undo, serialization/reopen and multi-property changes.

## Design layout

Design text flows from the saved frames and each record's resolved values. Unrotated text layers in an overlapping horizontal column stay below earlier text layers, preserving authored positive gaps; adjacent columns and rotated overlays keep their independent positions. Transparent text-bearing shapes from older drawing conversions follow the same rule. An empty `Other fields` slot collapses only when no independent artwork occupies its vertical band. Decorative parts retain their placement, and automatically sized cards grow to contain the text. An exact, non-soft height chosen by the user still wins: the card retains that height and reports `spills` when its content needs more. These are rendering rules for existing designs, with no persisted layout metadata or migration; the canvas and exports share them. While editing, temporary automatic text colors are re-resolved against the current card background and panels without writing a transaction. Explicit colors remain explicit.

## Shapes

**Records**, keyed by id in a state `{ [id]: record }`:
`{ kind }`, `{ at, edge, field, value }`, `{ at, edge, choice }`, `{ at, edge, tag }`, `{ args: [{ edge, at }], field+value | choice | tag }`. A record may carry `since` and `before` (ISO days). Values are canonical: a percentage is a fraction (0.716), a date an ISO day, a day of the year (a fiscal year end, datatype `yearly`) ISO's --12-31, money a number, a document its address.

**Trees.** Specifications, patterns and a record's own tree are nested:
- an object node: `{ id, kind }` an object, `{ kind }` a kind, `{}` unlabeled;
- any other node: `{ out, args: [{ edge, loc }] }`, where `out` is `{ field, value }` a value, `{ field }` a datatype, `{ choice }` or `{ tag }`, and is absent where the label is removed;
- in a pattern only, `{ open: true }` (`Tree.OPEN`), a location left open: any record fits it, whatever its shape, so one relation has a side of several kinds of record. A relation's one pattern, for a tree of it, is `N.relationPattern(t)`: its Name note's, where that leaves a side open (Evidence), else the tree with its labels removed. A record is at it by its id as usual: Evidence is `{ args: [{ edge: 'Document', at: docId }, { edge: 'Evidenced', at: ownershipOrPositionOrSigningId }], tag: true }`.

Edges keep their labels; argument order doesn't matter.

**Notes**: `{ note: id, label, pattern, view?, param?, value }`. `view` is a View object's id. `param` names one of a relation pattern's edges: the Name there is that role's list name (Owners), the Order its place among the edges. Labels: Name, Description, Order, Required, Check (TRUE at a definition whose ruled-out records are problems, as Required makes a blank one), Start, End, Formula, Shown, Caption, Position, the format properties (Shape, Fill, Outline, Weight, Dash, Frame, Layer, Arrow, Connector, Above, Font, Size, Bold, Italic, Underline, Color, Align, Format: `Notes.FORMATS`), and a view's own, at its View object: Layout (`{ rows }` for a table, its rows a kind `{ kind }`, a relation's edges, or a datatype; none for a chart), As Of (the day it keeps), Page (a paper's name, `{ size, portrait }` or `{ w, h }`) and Scale (`{ scale, x, y }`, what the page keeps, written with the kept places: how much smaller the chart is drawn, and how far it's moved). Footer, at the kind View at no view, is the chart's footer, `{ text, number }`. A Size, as a Weight, is in points as printed. A Formula note's value is its rows, `[{ label, formula }]`; a Position is `{ x, y, w }`, with `loose: true` where it was only a first place (a box added by a double-click) that gives way to the layout once a line relates it, and `kept: true` where a change kept it where the layout put it; a line's is its label's, `{ along, dx, dy }` (see `Layout.pin`); and `{ order, around? }` is what Tidy leaves of a place: where the box stood across, no place of its own.

**Rows and changes.** A row is a version of an item and names the item under its type: `{ id, chart, name }`, `{ id, spec, tree }`, `{ id, record, …record }`, `{ id, note, …note }`, `{ id, shape, … }` (a shape mustn't use those five keys). A change is `{ id, who, when, chart, note?, removes: [row id], adds: [row], reverses?, restores? }`: `note` says why, in words; `reverses` names the change it reverses, and `restores` the change that deleted an item it restores. A row is live if added and not removed. The file is `{ "dendra": 1, "changes": [...] }`.

## Tree

- Text: `clean`, `norm` (clean, lower case), `same`, `plural`.
- Records: `isObject`, `isField`, `isTag`, `isChoice`, `isRelation`, `isView` (an object of the app's own kind, View), `typeOf` ('object', 'field', 'tag', 'choice'), `argsOf(r)` → `[{ edge, at }]`, `rootLabel(r)`.
- `treeOf(recs, id)`: a record's tree, or null if a location is missing. Memoized per state, so never change a state in place. `parameterization(recs, id)`: its parameterization's key, as formulas.js keys what a definition covers.
- `index(recs)` → `{ entries, relations, kinds }`, Maps from a record id (or a normalized kind) to ids. `within(recs, id)`: the record and its owned entries, nearest first, without following relations into other objects; missing roots return an empty array and cycles are visited once. Its cached result is read-only. `dependents(recs, ids)` also follows relations, for deletion. `pathOf(recs, id)`, `objectOf(recs, id)`, `entryAt(recs, id, edge)`.
- Patterns: `specOf(t)`, `bare(t)` (root label removed), `key(t)`, `paramKey(t)`, `shapeOf(t)`, `weight(t)`, `narrower(p, q)`, `isOpen(t)` (whether it leaves a location open), `fits(recs, id, p)`, `idsIn(t)`, `rename(t, p, from, to)`, `renamed(node or row, from, to)`, `lift(t, p)`.
- `schema(trees)` → `{ [key]: spec }`, closed under locations. `schemaError(S)`: a sentence, or null.
- Values: `DATATYPES`, `PHRASES`, `MONTHS`, `parseDate(text)` → ISO or null, `parseKnown(text)` → a day, or a date known to its month or year, ISO's own 2022-03 or 2022, or null, `firstDay(iso)` its first day, `notA(datatype)` what doesn't read as one is said to be, `parseYearly(text)` → --MM-DD or null (December 31, 12/31, or a date's month and day), `formatDate(iso, 'long' | 'short' | 'month')` (February 14, 2023; Feb 14, 2023; February 2023; a day of the year without its year), `isoOf(date)` (the day a moment falls on, here), `classify(text)`, `parse(datatype, text)` → value or undefined, `format(datatype, value)` → text (a percentage to four places), `outputText(r)` (a record's output: its value, its option, a tag Yes or No), `isNumber`, `isAddress`.
- `linkOf(address)` → `{ link, system, kind, name, id, short, host, site, library, folder, sharing }`: what a document's address points at (SharePoint, OneDrive, EDGAR, NetDocuments, iManage, a file share or the web). A document reads as its `short`.

The executable [classification comparison](../tests/classification-test.html) models the same employment chart with `Person`/`Company` kinds and with one `Object` kind plus `Category` choices. The latter shares `Name`/`Country` declarations, places `Born`/`Revenue` under the appropriate choice, and locates relationship ends at those choices. Both models produce the same object names, relative merge fields, category/kind designs and SVG text. `Tree.within` gives the inspector, formatting and Scene one definition of owned entries; field discovery includes blank fields applicable at active choice locations, and relationship lists reach those locations while naming their owning objects.

Merge-field suggestions use short labels while they are unambiguous. If active branches both have `Code`, they offer `Home › Code` and `Work › Code`, including applicable blanks. Existing `{Code}` tokens keep their previous nearest-first reading. Own-field suggestions retain their source `paths` separately from the display label, so reusing a short nested field can preserve its schema location.

This is a comparison, not a migration recommendation. A classification adds an entry per object. More significantly, changing a populated classification retains its dependent fields and relationships, and the log infers new specifications from them: the old role constraint is not enforced after reclassification. The fixture captures this behavior. Removing kinds would first need an explicit policy for those transitions. The [GUI classification flow](../tests/builder-test.html?flow=classification) verifies blank-chart authoring, conditional fields, canvas drag, independent values and choice changes through controls. Existing constrained relationships can be used in the GUI, but the new-connection form does not yet let an author specify both endpoint classifications.

## Notes

`Notes.index(noteRows)` returns a reader. `Log` builds one per chart: `wb.notes(chart)`. Each `t` below is a tree: a record's (`Tree.treeOf(state, id)`) or any pattern.

- `resolve(label, t, view?, param?)` → `{ value, note }` or null: the note that decides. `value(…)` → just the value.
- `name(t)`, falling back to the kind, the edge, or a relation's edges joined by ' · '. `listName(t, edge)`. `edges(t)`: a relation's edges in order.
- `description(t)`, `order(t)` (an entry's place among its location's entries, by the Order at its label, read without its output), `optionOrder(p)` (an option's place in its list, by the Order at the option: Main Fund before Feeder Fund; none, by name), `required(t)`, `fixed(t)`, `changing(t)` (a Fixed note, true, says one fact for all time; false, of a date, that it recurs), `check(t)` (a Check note on a definition: one ruled out is a check failed), `heeds(t)` (one on an entry typed by hand: its "no" needs attention, and is no error), `isStart(t)`, `isEnd(t)`.
- `shown(t, view)`, `position(t, view)`, `caption(t, view)`, and `formats(t, view)` → `{ [label]: { value, note } }` for every format property a note decides.
- `styles(view)` → `[{ pattern, key, order, outputs: [{ pattern, formats: { [label]: value } }] }]`, in the view's order. An output pattern with no root label applies to every output.
- `definitions(schema)` → formulas.js's input, one per Formula note: `{ id, name, covers, rows, type, datatype?, options?, edges? }`. `relations(schema)` → `[{ name, type, edges, lists: { [from]: { [listed]: name } }, covers }]`. `relationPattern(t)`: the one pattern of the relation a tree is of.
- `fitting(schema, p)`: the specifications fitting p. `notes(label)`: every note with that label.
- **The chart's words**, for a record in a state `recs`: `nameOf(recs, id)` (an object by its Name entry, a view by its Name note, an unnamed object as its kind; a relation by its name; an entry by its label), `shortOf` (Short Name where room is short), `sides(recs, id)` (a relation's arguments in its edges' order), `placed(recs, id, args?)` (the place rule: a relation's sides in that order, each `{ edge, id, text, join }`, its object by its short name after the words joining it to those before; two as their line joins them, Cayman GP → Offshore Feeder; three or more as the two-box panel's sentence says them, less its verb, Margaret A. Chen for Fund III, via GP III, and a side already said not again, Margaret A. Chen for The Manager; a side named by a number with its kind, AIV-1, tax year 2025; `args` for a relation not recorded), `segmentOf` (a step on a path: Fund III, Jurisdiction: Delaware, Not Good Standing, a relation as `placed` joins it), `placeOf` (the path to a record, step by step: Fund III › Jurisdiction: Delaware) and `whereOf(recs, entry)` (an entry's place as far as it needs: its object, AIV-1, or the path where its object has another entry of its label; at a relation, the relation's place). Everything that names where a record is reads these: the formula bar, History, the inspector, the Dates table, the calendar and the skill's tool.

**The narrowest decides.** Among the notes with a label whose pattern t fits (and whose `param` matches), every note in the view comes before any in no view. Then the pattern with the greater weight wins, and then the lower note id. Notes in other views don't count. Where notes reach one mark through different records, `styles(view)` gives the order, and the later style wins.

**In a view, Order orders its styles** (their stacking). With no view, it orders entries among their location's entries, or a relation's edges (with `param`), or the views (on a View object). A note at one object or one value belongs to that record alone, not to a style.

**A view's look** (dendra.md, Workbook): `Notes.houseLook(rows, view)` → `{ notes, order, furniture, page?, footer? }`, what of a chart view names no record, with its paper and the chart's footer. `Notes.takeLook(tx, rows, view, look, { begun?, has? })` writes it on tx for a view, `begun` a view just made, whole, its paper and footer among it, `has(pattern)` whether this chart has what a pattern reaches; → `{ left }`, how many settings didn't come. `Notes.lookFrom(data)` → a look read from a file, what a look may hold and nothing else, or null.

## Log

`Log.open(json | changes | workbook?)` → a workbook `wb`. `Log.today()`, `Log.newId()`, `Log.validOn(row, day)`, `Log.typeOf(row)` (its item's type), `Log.latest(rows)` (the version with the latest start), `Log.outOn(notes, recs, id, day)` (what a start or end entry keeps out of the chart on a day: what it's at, where it starts after the day or ends by it; else null).

Reading, per chart:
- `wb.asOf(chart, day = today)`: the chart as of a day, a state. A record holds when its row is valid on the day, the day falls from its start entry and before its end entry (Start and End notes), and its locations hold. Memoized per day; a change keeps what it leaves as it was: a chart's notes where it adds and removes none, its schema where it gives records only other values or periods, and other charts' readings whole. A chart with a Years note at a kind (dendra.md, Time) has that kind's objects from the calendar, by ids of their own (`·2026`), read as any of its rows (`wb.rows`, marked `calendar`) and in no change, none writable: from the year before its first change, or the first year a row is at, to next year or the last a day's been asked of.
- `wb.at(moment)`: the log as it stood then, a workbook.
- `wb.schema(chart)`: spec items with every version of every live record, closed. `wb.notes(chart)`: the Notes reader.
- `wb.rows(chart)` (live), `wb.item(chart, id)` (an item's live rows, earliest first), `wb.charts()` (live chart rows), `wb.changes()` (all, by time). `wb.named(chart)`: what objects have been called, on any day, a Map of each name normalized (and "The BDC" as "bdc" too) to the set of objects it's been of.
- `wb.deleted(chart)` → `[{ item, type, rows, change }]`: items with rows and none live, each with the change that deleted it (the last to remove one of its rows) and the rows it removed.
- `wb.disagreements(chart)` → `[{ rows: [{ row, who, when, change }] }]`: live rows that disagree, versions of one item that differ and are valid on a common day, or records of two items with one argumentation; each group earliest first.

Changing:
- `wb.edit({ chart, who, day?, when?, note? })` → a transaction; `note`, why, in words, is kept on the change, and History shows it. `tx.add(type, payload, id?)` → id. `tx.set(id, payload)` makes a new version; `tx.update(id, changes)` makes one from the version in force, changed. `tx.remove(id, day?)`, on the transaction's day, or on the day given (null for none: a deletion that asks its own day). `tx.note(label, pattern, value, { view, param })` sets the note at exactly that pattern, or removes it when `value` is undefined. `tx.keep(rowId)` settles a disagreement: the rows that disagree with it go. `tx.rename(p, from, to)`. `tx.moveUp(p)`. `tx.asOf(day)`: the chart as the transaction would leave it, unmade, as `wb.asOf` would read it then, start and end entries and locations included, each record it leaves as it was the very object `wb.asOf` gives. `tx.says(text)`: what the change says of itself, one act of many rows, kept on it as `says`, which History and Undo say in place of going through them. `tx.commit()` → the change, a sentence saying why not, or null if empty.
  - With a `day`: an added record starts on it, setting a record splits its validity there (the old value before, the new from), and removing ends a record and its dependents there.
  - With none ("Today"): setting corrects the version in force, keeping its period, and removing deletes, taking along the item's dependents, the notes at it, and a view's notes and shapes.
  - `rename` reaches every tree narrower than p: records (all versions), specifications, notes' patterns, list names and a table's rows. Wherever a name changes (a label, a kind, an option, or a Name note's value: a relation's name or a list's), every Formula row citing it is renamed too, where formulas.js offers `renameName`. `moveUp` reaches the same trees.
- `wb.apply(change)`: the change, or why not. Refused if it removes a row that isn't live, or newly breaks the timeline (two records with one argumentation valid on a common day), a location, or the schema's conditions.
- An amendment (dendra.md, Change) is one change with `amends`, the change it amends. `tx.unmake(changeId)` takes back what that one recorded, its records' rows alone, and says it amends it; the act is then made again on the same transaction, keeping its ids. `wb.canAmend(changeId)`, while its record rows are live; `wb.took(change)`, what it took away, in place of what it amends, which an amendment reads back by. `tx.revise(row, row2)` gives a row other days or another output, or takes it away; `tx.redate(id, 'since' | 'before', from, to)`, the day a record and what's at it hold from or end on; `tx.amends(changeId)`, where nothing's reversed. `tx.rekind(id, kind)`, an object given another kind, every version. `tx.added()`, the rows it adds so far.
- `wb.reverse(changeId, who)`, the reverse of a change, and `wb.canReverse(changeId)`: what Undo and Redo, which a window keeps for itself, and undoing an older change make. A change can be reversed while rows equal to the ones it added are live, so reversing several changes to one record in turn works. `tx.reverse(changeId)` does the same in an edit, unmade, for its redline. `wb.at(moment)`, the log as it stood then, has `moment`, so a scene of it can say the moment on its page, and a file exported then in its name: `Log.stoodText(moment, style)` makes those words ("As it stood on December 31, 2036, 3:15 PM"; `style` as `formatDate`'s). A change may carry a `note`, a line of why, which History shows; `wb.reverse` takes one as its third argument. `wb.annotate({ chart, who, about, note })` gives a change a reason afterwards, as a change with no rows that says what it's `about`; `wb.reasons(changeId)` → `[{ text, who, when, own, change }]`, its own note and the annotations standing.
- `wb.restore(chart, item, who)`: restores an item deleted, as a change that removes nothing. It adds fresh copies of the rows the change that deleted it removed of it and of what was at it then: the records located at it, at any depth, and the notes and shapes at those (a deleted view's notes and shapes too). Whatever else that change did stands, so restoring one payment a revision removed brings back that payment and nothing more. What was at it and is also at something still deleted stays deleted, and comes back with that. The change, or a sentence saying why not (an item can't come back without what it's at: "Something it’s at no longer exists."), or null if the item isn't deleted.
- `wb.merge(other)`: takes in another log's changes (a workbook, JSON or an array): the union. `wb.subscribe(fn)` → unsubscribe; `fn(changes)` runs after each apply or merge.
- `JSON.stringify(wb)` saves; `Log.open(text)` loads.

## Formulas

Records worked out from other records, as formulas.md describes. It takes the entered records as of a day, a state, and from the chart's Notes reader `definitions(schema)` and the names `{ relations: relations(schema), schema }`. A name the schema has, on any day, is nothing where no record has it; only a name it never has is `#NAME?`. A row's formula starts with `=` (gives a value) or `←` (`<-` as typed), short for `= IF(c, TRUE)`.

- `computeState(entered, definitions, names, from?)` → R. It starts from the closest of `from`, an earlier R, and the latest workings-out (so a change made after its preview starts from the preview, and its Undo from the chart before it, entered records compared by what they say); where nothing it reads has changed since that one, it gives that one again; and it works out again only the groups of definitions that the change since reaches; the rest come back as they were left. A group it reaches is worked out again, where it can be, only at the candidates that read what the change reached, round by round (the rest kept, each record out of sight until its round), so R is always what a working-out from nothing gives; `null` starts from nothing. R has `records` (entered and computed; a computed one has `computed`, its definition's id, and an id from its argumentation, `computedId`, stable across workings-out); `computed` `{ [id]: { def, row, label, holds, stage } }`; `covered` `{ [entered id]: { def, row, label, holds, value, agrees } }` (what the rows give where an entry stands, which wins); `errors` `[{ def, id, args, at?, error: { code, msg } }]`, each where its record would be (an entry's `args` its one, `[{ edge, at }]`, beside its `at`), and `#N/A` "Needs Fiscal Year End." where a value the row wanted was blank; and `defErrors`; `loops` `{ [def]: [{ row, from, to, monotone }] }`; `uses` `{ [def]: [def] }` (what each definition reads); `flaws` `{ [def]: [{ row, from, to, code, message, fix?, lit?, value?, label?, warn? }] }`, what's wrong as a rule's written, read off its rows (a `warn` is said, and isn't an error); `rows`, `order`, `steps`, `ms`, and `state`, the engine's own.
- `broken(R)` → `{ roots: [{ def, name, code, problems }], reach: Set of def }`: the rules in error (formulas.md, Errors), and those and all that read them, at any remove. `asDrawn(R, state)`: the state with a tag a rule in error gives drawn as one that doesn't hold (what `Scene.of` draws, given `computed`). `sideObjects(R, def, edge)`: the objects a definition's records have at an edge.
- `ground(R, id, { all }?)` → why a record is there, as records: `{ id, def, entered, stage, rows: [{ row, label, stage, parts: [{ id, from, to, items? }] }] }`; `rows[0]` is the ground, of least stage, and unfolding it ends at entered records. With `all`, the rows are every one that holds in the finished state, each a ground a person can be told of, though one may lean on a record of its own round.
- `evaluateRow(R, def, row, at)` → `{ value, names: [{ from, to, ids }], parts: [{ from, to, values }] }`: a row (its index, or a formula as typed) worked out at a record, or at `{ [edge]: object id }` for a pair that has none. `evaluateAt(R, text, at, names?)` works an expression out at a record (or none), with `names` given values (`{ '@AsOf': date }`). `text(R, value)`: a value as `&` reads it.
- `names`, the third argument of `computeState`, takes too `day`, the day shown, which `TODAY()` reads (the clock's where none's given), and `named`, `wb.named(chart)`, what objects have been called on any day, by which a rule can point at one; what they're called in `entered` counts where it's left out.
- `attention(R, N, day)` → `[{ kind, id, edge?, error?, by? }]`: what needs attention on a day, as the status bar counts it. A date a formula gives, or an entry one covers, is `overdue` once the day is past it and `soon` within 30 days. A required entry missing is `blank`, with its record and edge, and so is what a rule can't say for want of it, `by` that error (a `#N/A`, whose `error.blanks` are `[{ name, at }]`), once for each. A record ruled out where a Check note says so is an `error`. A check that can't say is `cant`, its `error` that `#N/A`, as well as the blank it wants. Each other of R's errors is `broken` (its `error`), and so is a rule in error that shows at no record, `rule:` and its id. A value typed over what a rule says is `overrides`.
- `coverage(R, def)` → `{ holds, fails, cant, typed, broken, quiet, silent, says }`: what a definition says of what it covers, each by id, `quiet` those it says nothing of (null for a relation), `silent` what that means, 'untested', 'no' or 'fine', and `says` how many it answers at. `readsAt(R, def)`: the names its rows read of the record they're at.
- `pay({ R, due, day, add })`: a payment of a tax owed year by year (dendra.md, Time). `due` is a date worked out at a relation of a record and a year, until the entry its rule reads by ISBLANK is entered (Annual Tax Due, until Annual Tax Paid); the payment goes to the earliest year of that relation at the same first side whose due date is still given, as `add({ at, edge, field: 'date', value: day })`, `add` entering that year's relation where a formula gives it. It returns the year settled; or null where `due` is no such date.
- `silence(N, S, recs, at, edge)`: what a tag's definition says by saying nothing at the record `at` (dendra.md, Definitions: Not tested), where it covers it and its entry is specified at a record of that kind: `'untested'`, its rows able to say both yes and no; `'no'`, only yes; `'fine'`, only no; else null.
- `diff(before, after)` → `{ appear, go, change }`. `check(text, { computed, def })` → `{ kind, problems }`. `suggest(text, cursor, { computed, def, at })` → `{ from, to, list }`.
- `tokenize(text)`, `splitFormula(text)`, `tidyArrow(text)`, `renameName(text, from, to)`, `nameText(name)` (bracketed where it isn't one plain word), `KEYWORDS`, `FUNCTION_NAMES`, `isError(v)`. Spans are character offsets into the row's formula, prefix included.

## Templates

[templates.js](templates.js) is the registry; [../templates/](../templates/) has one classic script for each, registering `{ id, name, order, rows, example }`. A row is as the log keeps it, less its id, its item named for now: `{ tree }` a specification, `{ record, kind: 'View' }` a view, `{ label, pattern, value, view?, param? }` a note, `{ shape, view, … }` a free shape, and the one whose role is `title` says the chart's name. `Templates.rows(write)` is the pen a hand-written template writes them with; `Templates.begin(tx, t, title)` writes them under fresh ids; `Templates.exampleOf(tx, t)` writes its example records, which its card in the New chart gallery draws. `fund-structure.js` is generated from the sample, what `App.newChart` makes of it: canvas-test checks the two are one.

## The sample

[../sample/calder-ridge.js](../sample/calder-ridge.js) holds one chart, `calder-ridge`, in 137 changes by three authors, from June 2024 to Friday, October 23, 2026, each the team's own: what was built or migrated since is folded into the rows it fixed, as if the chart had been kept that way from the start. Its views are the View objects `view_main` (Structure), `view_40act`, `view_fund3` and `view_control`, drawn as charts, and four laid out as tables by their Layout notes: Entities, Ownership, Dates and Documents. Definitions keep their old ids (`def_tax`, `def_control`…). The 40 Act filter is the tag BDC Affiliate (`def_bdc_affiliate`), shown by its output; the other two filters are Shown notes by kind and Vehicle Type. Five definitions are checks: Formation Document on File, Governing Agreement on File, Ownership Adds Up, Percentages In Range and Capacity Held. The feeder's GP change, the Corvane closing, renewed filings and status changes are dated rows. The registered agent once recorded for Fund III and GP III, The Corporation Trust Company, is deleted, and can be restored. Each Delaware tax, a corporation's franchise tax among them, is a relation of the taxpayer's jurisdiction and a Tax Year, its payment an entry there.
